### 1.2 组件交互流程

#### 软件包发布流程：
1. 用户通过DCPM CLI发布软件包
2. DCPM服务将包元数据写入共享区块链
3. 系统检查可用UFS节点，优先上传到UFS网络
4. 同时将包内容分发到IPFS/BT网络作为备份
5. 返回发布成功的区块链交易ID

#### 文件下载流程：
1. 用户请求下载软件包或文件
2. 系统查询区块链获取元数据和可用源
3. 优先从最近的UFS节点下载
4. 如果UFS不可用，从IPFS/BT网络获取
5. 验证内容哈希与区块链记录匹配

### 2.3 跨协议通信设计

#### UFS节点广告协议：
```python
class UFSServiceAdvertisement:
    def __init__(self, node_id, endpoint, capabilities, load):
        self.node_id = node_id  # 16字节哈希
        self.endpoint = endpoint  # "ip:port"
        self.capabilities = {
            'dcpm': True,  # 是否支持DCPM协议
            'storage': 1000,  # 可用存储(GB)
            'bandwidth': 100,  # 可用带宽(Mbps)
            'geo': [31.2304, 121.4737]  # 地理位置[lat,lng]
        }
        self.load = 0.5  # 当前负载系数0-1
        self.timestamp = int(time.time())
        self.signature = None  # 节点签名
```

#### DCPM-UFS节点发现协议：
1. 新节点加入时广播`UFSServiceAdvertisement`
2. 现有节点响应`AdvertisementAck`包含:
   - 距离指标(基于地理位置和网络拓扑)
   - 推荐的其他节点列表
3. 新节点构建最优连接列表

### 2.4 混合存储策略

```python
def select_download_source(package_id):
    # 1. 检查本地缓存
    if package_id in local_cache:
        return {"type": "local", "path": local_cache[package_id]}
    
    # 2. 查询区块链获取元数据
    meta = blockchain.query(package_id)
    if not meta:
        raise Exception("Package not found")
    
    # 3. 优先选择UFS节点(按距离和负载排序)
    for node in sorted(meta['storage']['ufs_nodes'], 
                      key=lambda x: distance(x) + load_factor(x)):
        if check_node_available(node):
            return {"type": "ufs", "node": node}
    
    # 4. 尝试IPFS回退
    if 'ipfs_cid' in meta['storage']:
        return {"type": "ipfs", "cid": meta['storage']['ipfs_cid']}
    
    # 5. 最后尝试BitTorrent
    if 'bt_hash' in meta['storage']:
        return {"type": "bt", "hash": meta['storage']['bt_hash']}
    
    raise Exception("No available sources")
```

## 5. 性能优化策略

### 5.1 缓存层级设计

1. **内存缓存** (LRU策略)
   - 最近访问的包元数据
   - 热门文件块

2. **本地磁盘缓存** 
   - 已下载的完整包
   - 部分下载的文件块

3. **邻近节点缓存** 
   - 同一局域网内的节点内容
   - 地理位置相近的节点内容

4. **持久化存储**
   - 显式固定的内容
   - 系统关键组件

### 5.2 预测性预取算法

```python
def prefetch_algorithm(user):
    # 基于用户历史行为
    frequent_packages = get_user_history(user).most_common(3)
    
    # 基于依赖关系
    dependencies = []
    for pkg in user.current_project.packages:
        dependencies += get_package_dependencies(pkg)
    
    # 基于地理位置偏好
    geo_preferences = get_geo_preferences(user.location)
    
    # 组合预取列表
    prefetch_list = unique(frequent_packages + dependencies + geo_preferences)
    
    # 智能调度
    for pkg in prefetch_list:
        if has_storage_capacity() and has_bandwidth():
            prefetch_package(pkg, priority=calculate_priority(pkg))
```

## 6. 监控与指标

### 6.1 关键性能指标(KPI)

| 指标名称                | 计算公式                          | 健康阈值       |
|-------------------------|-----------------------------------|----------------|
| 区块链同步延迟          | max(本地高度 - 网络高度)          | < 3 blocks     |
| 包下载成功率            | 成功下载/(成功+失败)              | > 98%          |
| 平均下载速度            | ∑下载速度 / 下载次数              | > 5MB/s        |
| UFS节点响应时间         | 从请求到第一个字节的时间          | < 500ms        |
| 内容可用性              | 成功检索次数/总检索次数           | > 99.5%        |
| 区块链存储增长          | 每日区块数据增长量                | < 100MB/day    |
