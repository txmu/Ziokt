# v1.0 审计与发布验证

本批源码修复及验证流程适用于 Ziokt、Corium、Shadow6 与 Releases 管理器。
最终发布证据在 v1.0 的 RELEASE_EVIDENCE.json 中记录精确提交、实际 CI、
产物摘要及未完成边界；本文件说明实现与验收契约，不提前宣布 CI 通过。

修复包括：OCI 失败回执未初始化、无效缓存挂载、缓存恢复与读写模式、无绑定旧键回退；
社区原生命名密钥类型；匿名域名大小写、结尾点和 IDNA 点变体触发直连 DNS；
OpenCI 私有项目的公共元数据发布；Content Fabric 包名跨项目冲突；恢复链缺失高度；
部署器跨节点凭据回退、自定义服务名、响应重定向及启动产物/工具不完整。

OpenCI 发布默认保持项目私有，显式 `release-configure --visibility public` 才公开。
持久 outbox 保存最初选择，重试不会因配置改变而扩大可见性。
旧版本已经公开的记录不会被伪称从未泄露，升级时应由其所有者审查和撤回。

形式化对应不只依靠文件哈希：`formal/contracts.json` 的受限类型表达式生成实际
运行的 Python 判断和 Lean 中的同一约束；CI 拒绝任一生成结果漂移，并检查实际
调用入口仍引用这些判断。自然数拒绝负数、布尔冒充整数及浮点数，避免超出证明域。
Lean kernel 与公理检查、源码哈希、真实 SQLite/HTTP/OCI/原生回归共同构成证据。
生成器、Python/Lean 基础语义、密码学、数据库和操作系统仍是明确的信任边界，
没有把整个程序机械地精化为 Lean。

三仓源码清单由 `tools/formal_coverage.py` 生成。Ada/SPARK 和 Idris 既有原生契约
作为已有证据保留；未建模代码、FFI、第三方依赖和物理平台单独记录。

系统门槛：

- `formal-joint.yml`：三仓精确 revision、Lean、对应检查及真实边界回归。
- `system-acceptance.yml`：真实 TLS 重组/同步/公告、失联、回滚、检查点、历史重放、
  双链/DNA/协作治理，以及匿名载体失败时的拒绝直连行为。
- `openci-core.yml`：真实 OCI、独立重建、Content Fabric 对象、签名 dCPM/UFS 安装、
  离线验证，再将同一构建回执用于原生治理、贡献结算与 Phoenix 历史重建。
- `integration.yml`：便携平台、原生联邦、真实 Tor/I2P、NAT 和全量回归；编译只在 CI。
- Releases `independent-deployment.yml`：三个独立根目录、独立身份、同一公开创世、
  自有 Gateway/ZDNS/MCP/OpenCI/奋斗、种子停机后存活节点互通及服务重启。

实际生产路径：PoW 生产与重组/历史重放共用 `_corium_work_consensus` 的验证；
`ANNOUNCE_BLOCK` 只作签名发现线索，进入同一重组与交易验证路径，不能凭公告
取得接纳权；同步通过同一原生重组提交，失败不能改变已接受的语义状态。
新增测试将这些入口放在同一 CI 验收矩阵中，保留每条实际路径的证据。

同一 CI 主机上的多个进程不是多个物理故障域。全球流量关联、所有运营商封锁、
实体设备长期运行、生产主网全部历史可信性仍须独立部署证据；不使用配置开关、
源码模型或单次握手替代这些结论。
