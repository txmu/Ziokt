# ETP database reopen and simultaneous reconnect review

The integrated native CI exposed two lifecycle failures. sled 0.34.7 wraps an underlying `WouldBlock` file lock in `ErrorKind::Other`, so the previous reopen test rejected a genuinely transient lock. `ChatStore::open` now retries only native lock contention for at most two seconds; permission, corruption and other I/O failures still fail immediately. The lossless quarantine migration runs after a successful open. A focused classifier regression covers the wrapped lock and unrelated errors.

Inbound authenticated handshake replacement and an explicit outbound reconnect previously could both inspect an old session and then overwrite each other's replacement. Sixty-four bounded async lock stripes now serialize those transitions for each peer. Existing session locks continue to protect reliability state and offset transfer. Authentication, incarnation binding, simultaneous-flight arbitration and obsolete-handshake rejection remain mandatory.

The existing real UDP regression covers a new Engine on the same socket, stream-offset reset, same-incarnation rekey, obsolete IK3 rejection and three simultaneous reconnects. The quarantine test exercises real sled files and verifies retained bytes. These Rust tests and native builds run in CI. Local verification for this change parses both files with rustfmt and does not compile native code. A green CI run is required before accepting the resulting binaries.

A deployment check additionally found the gateway returned its native statistics text directly where the adapter requires an object. The v1 gateway now places the real Engine statistics in `native.summary`. The real four-process CI smoke test also invokes `etp.health` with fresh challenges, so successful builds must satisfy the same typed health contract used by production.

A second intermittent reconnect failure exposed stale session references in the send and timer paths. Offset reservation, current-session lock acquisition and timer snapshots now use the same transition guards as handshakes. Queued sends carry the authenticated remote incarnation, and timer expiry/retransmission is conditional on the exact current session, so an obsolete snapshot cannot remove a replacement or replay an old handshake flight. The real UDP regression reports its failure stage and CI repeats it eight times for each native feature profile after the full library suite.

Repeated real reconnects also exposed an independent congestion-credit leak: expired packets left the reliability queue without releasing NewReno packet credits. After multiple losses the reduced window could remain permanently full even though no packet was awaiting an ACK. The reliability layer now reports the exact expired packet count; NewReno retires those credits before applying debounced loss-window reduction. Existing custom/FFI strategies retain their default loss callback. Two deterministic regressions verify exact batch accounting and retransmission after a full timeout without fabricated ACKs.
