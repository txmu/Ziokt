# 独立轻量客户端的任务协调

客户端无需彼此通信，由接收贡献的节点分配工作。多个浏览器、设备或服务实例
共同使用节点的私有 SQLite 协调状态，不共享客户端密钥。

- 零号引擎按网络、贡献地址和原生题目持久分配连续、不重叠的 nonce 区间。
  SQLite 写事务保证并发分配及重启不会复用区间。页面中的线程继续按步长划分各自区间。
- 一道零号题目提交成功后停止派发，其他客户端每三秒检查任务状态并停止旧工作。
  待确认回执仍不是链上确认；任务换题后再领取新工作。
- GIMPS 使用独占任务租约。客户端生成随机私有标识，只有同一标识可以重新领取
  自己的 token；其他客户端领取其他指数。Corium 的只读 challenge 支持最多 128 个
  `exclude_exponents`，仅过滤当前原生题目，不允许客户端伪造新题或改变验证规则。
- 租约 120 秒到期，活跃页面每 15 秒发送心跳和检查点。断开或关闭后，其他客户端
  可以接管到期题目；旧 token 的心跳和提交被拒绝。服务重启保留有效租约。
- 单个 GIMPS 指数的顺序依赖不能靠复制完整计算提高速度；现有页面保持一个计算
  Worker，多客户端并行处理不同指数。没有可用题目时等待，不重复别人的题目。

`tests/test_effort_coordination.py` 覆盖跨线程、跨实例分配、重启、任务完成后的取消、
独占租约和检查点到期接管。节点保留最终证明验证及原生签名提交权限。

Android 1.0.1 的单线程原生工作器使用随机 24 字节工作标识，按同一接口检查
零号任务、每 15 秒续租并上传 GIMPS 断点，网络断开或停止后终止计算；到期后
其他设备接管。原生 PRP 包含 Gerbicz 检查和转移证明，直接交由 Corium 验证。
Windows 1.0.1 在隔离 WebView2 中使用节点实时页面，并要求协调协议 v1，
旧节点页面更新后才启动计算；重启、停止和网络恢复沿用相同租约机制。
