# 私人分享、阅读同步与持久维护

私人分享的加密端点是发送账户和接收账户所在的节点保险箱。服务会为经过授权的
本地账户处理明文；传输中继、公开目录和其他账户得到的是密文，节点托管者仍属于
账户的信任范围。公开身份使用节点签名，联系人必须绑定已配置节点及账户；不接受
请求方提供任意网络地址。

## 使用

Library 的私人笔记区域提供“私人分享与阅读同步”控件，Web、Gateway GUI 和扩展
共用相同客户端。先显示自己的公开身份，双方交换公开身份并保存联系人。跨节点
联系人填写节点维护者已配置的 peer 别名；同节点联系人留空。分享有效期为 1–90 天。

`content.private.share` 创建持久分块任务；`step` 每次最多加密 16 个 16 KiB 块。
后台继续完成加密并取得接收节点签署的回执。接收方在私人收件箱下载，浏览器完整
校验后保存；浏览器上限 16 MiB，分块 API 支持节点声明的对象上限（最多 512 MiB）。
分享内容及阅读状态不进入公开 catalogue、搜索或公共事件日志。

每次分享使用新的 X25519 临时密钥和 HKDF/AES-GCM 数据密钥。账户私钥在本地保险箱
密钥下加密保存。后台每 30 天轮换账户分享密钥，刷新已固定节点签署的联系人身份，
为仍有效的对象分享重新加密。接收方 epoch 变化使旧授权不可读取，不能回退身份 epoch。
撤销递增授权修订并保留签名墓碑，重复交付幂等，旧授权不能复活。

每次读取检查来源节点的新鲜签名状态，状态挑战时限 60 秒；来源离线时暂停读取，
避免把离线缓存当作仍然有效的权限。撤销不能收回接收方此前已解密并另存的文件，
GC 也不宣称擦除对方机器、备份或 SSD 的历史物理位。

双方均开启联系人“阅读同步”后，后台分批加密同步 Library 阅读位置、私人笔记、书签、
馆藏与成员变更，以及 Netnews 阅读标记。同步使用 Lamport 时钟与设备节点 ID 确定冲突顺序，拒绝同一版本内容矛盾；
游标包含完整排序键，分页不会跳过同一时钟的并发状态。撤销同步许可停止后续交付。
同步数据在接收账户中重新加密持久化。个人条目的删除墓碑阻止旧副本复活，馆藏成员
使用逐项事件分页，避免把整个大馆藏塞入一个消息。

## 维护与回收

`content_server` 默认启用持久维护任务，也可在 `maintenance` 中设置 `enabled`、
`interval`（15–3600 秒）和 `gc_grace`。每轮最多检查两个对象、每对象八个块，记录
检查位置、失败和退避；发现密文损坏时从已配置来源取回块，验证已有 Merkle 根与
本机已提交摘要后原子替换密文。收到的私人密文也会分批复制、校验和缓存。
未找到真实可验证来源时记录 degraded，不把重新排队称为修复成功。

GC 保留活跃记录、别名引用、跨应用 pin 和未过期私人授权。显式按账户回收及后台
宽限期回收会释放原生 ChunkStore 引用、删除不再引用的密文文件、回收崩溃留下的
孤儿密文，同时保留撤销和公共撤回墓碑。上传空间不足时仅淘汰过期的副本缓存，
不以其他账户未发表的原始文件充当缓存。修复与回收操作均有固定预算。

新增证据：`tests/test_content_private.py` 使用两个真实环回 HTTP 节点验证加密分享、
轮换、撤销、物理回收、阅读状态收敛和真实块修复；完整长期压力及分区回归由 CI 执行。
