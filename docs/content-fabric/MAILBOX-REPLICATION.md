# ETP Mailbox v2 可选持久复制

此实现位于 `companions/etp/src`；原始归档不变。旧 `MailboxFlavor::new` 保持单节点构造方式。显式 `new_with_replication` 或 native gateway 的 mailbox.replication 配置才启用复制。

模式 copies=1/3/5 定义为**包含本机的总持久副本数**。远程成员必须正好为 copies-1，具有不同的固定端点和 Ed25519 身份；Gateway 还要求它们同时位于授权 ETP 加密传输邻居中。副本签名密钥与 ETP X25519 传输密钥分开。不能用同一个端点重复计数。

## 投递和确认

保留 v2 DEPOSIT/FETCH/DELETE。启用复制后，写入先产生持久日志，再修改邮箱并执行 sled flush。网络队列已接纳不是持久确认。远端验证钉住的节点签名、大小和配额，写入本地日志/邮箱并 flush，才签发绑定完整变更摘要的 ACK。发送端把 ACK 保存并 flush。

复制模式返回 `[2,5,status,copies_observed,copies_required]`，status=1 为 pending，0 表示已有目标数量的持久回执。单节点旧模式继续返回 `[2,5,0]`。操作 6 使用与 FETCH/DELETE 一致的用户签名证明，正文为 64 字节消息键，查询该投递或删除的回执。证明绑定操作码、时间、nonce 与消息键，不允许借用 FETCH 证明查询或删除。

这些是历史持久接纳回执，不是节点当前在线或磁盘从未丢失的证明。全副本确认策略当前要求所有选定成员；网络分区返回 pending，绝不降级伪造完整复制。copies=1 可在本地 flush 后完成。

## 元数据与权限

副本只得到原有 32 字节收件人标签、密文摘要、密文、到期时间及删除标记。不会收到收件人的原始公钥、FETCH/DELETE 的用户证明、明文正文或密钥。标签和密文长度仍有可链接性；这是密文复制，不是匿名性证明。

被授权副本能保存、转发原始签名变更。转发者端点与原签名者都必须属于固定成员集；保留原签名，不把转发者变成原发布者。副本成员是受信任的存储权限域；副本节点的接纳签名不等于收件人授权证明。

## 幂等、反熵、恢复

消息键仍为原 v2 的收件人标签加密文 BLAKE3 摘要。同一投递重试不会新增邮箱行。复制变更按完整签名帧摘要去重；回执绑定该摘要。

持久序列日志、peer 游标与每个消息最新变更支持有界重放。同步页只携带一条已签名变更；先持久应用，再推进游标。丢包可重试。原生宿主每五秒重试有界近期变更并请求增量页；队列满时保留磁盘日志，后续重试。构造时重放日志并应用墓碑；现有单节点消息在显式启用时加入复制日志。

删除先写墓碑；墓碑优先于旧投递，过期节点回归不能恢复同一消息键。墓碑长期保留，不声称远程物理擦除。原有消息 24 小时到期、4096 条总消息/每收件人 64 条及 8192 字节密文预算保持。复制日志限制 16384 条，达到限制拒绝新变更；尚未实现安全的成员 epoch 迁移与日志压缩，需离线检查点迁移，不得简单清空墓碑。

## 原生配置与工具

Gateway 可选配置：

```json
{"mailbox":{"database":"/private/mailbox","replication":{"copies":3,"signing_key":"LOCAL_ED25519_SEED_HEX","peers":{"127.0.0.1:19002":"PEER_B_ED25519_PUBLIC_HEX","127.0.0.1:19003":"PEER_C_ED25519_PUBLIC_HEX"}}}}
```

对应 native gateway 顶层 peers 另行配置各端点的传输公钥。Mailbox 使用复合 Flavor 的 stream 4，Forum 保留 stream 3。单机/旧配置不必增加 mailbox 字段。

ETP IPC/MCP 新增 etp.mailbox.status 和 etp.mailbox.request。request 只接收 v2 用户操作 1/2/4/6，不能通过应用工具发送复制控制包。健康响应不假定端到端已验证。MCP 使用原 etp:read/write 权限和写入幂等日志。

## CI 与限制

CI 矩阵 1/3/5 使用真实 Rust Mailbox、独立进程、独立 sled 路径、真实 UDP，覆盖投递、持久回执、离线删除、重加入、重启及旧投递拒绝。另保留旧 v2 签名/重放测试。该 runner 是复制机制网络验证；生产 ETP 加密连接、复合 Flavor 路由和公网部署需要独立测试。工作流未执行时不能宣称已经通过。
