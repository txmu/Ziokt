# 统一 GUI 的断网运行边界

GUI 所需脚本、样式、图标和中英词典均随源码/安装包交付，不使用外部CDN。在线首次安装PWA后，会完整缓存固定静态壳；缺任一资源时安装失败，不能报告离线准备成功。静态缓存版本取决于交付文件摘要，激活仅清理Ziokt GUI自身的旧缓存，不删除同源其他应用缓存。

两种使用方式：

- 本地交付包直接打开 `gui/src/index.html#ecosystem`，即使没有HTTP服务或网络也能启动应用与离线工作区。
- 已安装PWA或已完成缓存的网页，在断网时重载同一GUI入口；根目录和 `/gateway-assets/gui/` 部署均经过实际浏览器验证。

本地工作区提供有界SHA-256文件校验，文件不上传。设置、双语、主题和工作区可使用；需要原生节点的操作仍需实际本地节点。无法访问远端时不能把旧结果冒充新操作成功。首次从未访问过的HTTPS网页当然不能凭空取得安装资源。

“浏览器断网”和“AirGap进程策略”分别验证。前者由Playwright真实离线模式验证页面重载和本地计算；后者由 `test_airgap.py` 在新进程中验证联网/DNS/子进程被拒绝，以及本地代数、TC-16和离线文件交换仍可使用。当前策略不是操作系统隔离沙箱。

静态缓存严格限制到固定公开文件：不缓存Gateway/MCP/API响应、授权头、私有对象或任意导航内容。完整私人离线藏书、新闻附件缓存、密钥轮换及退出清理仍是单独的未完成业务要求，不能由静态GUI离线验收替代。

`tools/gui_offline_smoke.cjs` 在严格CSP下验证：两种部署路径、断网重载、原始文件校验、私人API未缓存、其他应用缓存保留、移动端筛选/布局和file://启动。CI以Chromium/Firefox/WebKit矩阵运行；本轮本机只运行了Chromium，其他引擎必须以实际CI结果为准。

WebKit存在[Playwright离线模拟缺陷#42775](https://github.com/microsoft/playwright/issues/42775)，测试对该引擎实际关闭源站监听端口后重载，不跳过缓存验证，也不把此结果描述为模拟全机断网。Chromium/Firefox使用浏览器网络离线模式。测试API响应与生产Gateway一致设置no-store，避免把浏览器HTTP缓存混同于Service Worker缓存。
