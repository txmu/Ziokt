# v1.0 GIMPS 发布核查

本轮复核范围：GIMPS 算术、浏览器工作者、PrimeNet 信任边界、持久化租约、原生模块打包及服务部署。未修改模块沿用既有验证；全量构建、压力与多物理节点测试留给 CI/后续独立部署阶段。

- 官方样例：未经修改的 mprime 30.19b20，下载地址和官网校验值见 `tests/fixtures/gimps/mprime-provenance.json`。M127/M521 的真实二进制 proof 分别 364/448 字节，以 Base64 无损保存，官方 JSON 的 MD5 也与文件一致。
- `gimps_files.py` 按实际 ASCII 头、little-endian 余数、SHA3-256 链和 v2 奇数轮次规则校验，逐余数篡改拒绝。v1 格式读取与算术路径保留，但本轮官方实测证据仅覆盖 v2、base 3、Mersenne、POWER multiplier 1。
- 原生 Corium 证明明确导出 `.corium-proof.json`，不冒充官方二进制 proof；导入官方 proof 先核验，再在容量允许范围内重新生成 Corium 证明。
- 检查点使用完整余数、相邻状态的折叠递推证明及 Gerbicz 分块乘积恒等式；拒绝重新计算哈希的伪造状态、奇偶性错误、非单位乘积、缺失检查点和容量绕过。未宣称与成熟 FFT 实现具有同等工程认证或固定 0.5% 验证成本。
- 浏览器实际 worker.js 的 M2/M3/M7/M67/M127/M521 产物经原生验证器核验。
- 任何 engine 字符串均不能放宽本机容量限制。默认原生指数 100000、估算内存 256 MiB；浏览器另有指数和运行时间限制。应用层估算不替代操作系统资源隔离。
- PrimeNet 只允许固定 HTTPS 官方端点、不跟随重定向、要求已记录任务号与注册 computer GUID；使用原始 Prime95 JSON 和真实 ar 参数。通用 success/accepted 文本不会算作回执。尚未向官方服务器提交本轮小素数，不宣称官方业务验收通过。
- 租约恢复按网络/签名身份隔离；检查点与操作日志同样分域；重复任务复用有效 token，完成 token 保存可跨重启重放的幂等回执，数据库状态优先于内存缓存。独立节点共享链状态的去重由 Corium 验证与结算完成；没有把本地 SQLite 租约宣称为跨机分布式排他锁。
- 6 个原始/配套 Python 文件的语法错误已修复，包括顶层 await；共同源码打包会编译检查最终全部 `.py.txt` 条目，而不只检查 AST。
- 原生 CI 包和部署器同时携带 gimps_consensus.py；部署同步更新解释执行入口及配套模块，并记录摘要。
- 本地全量测试/原生构建已取消并清理相关产物。差分回归与静态检查记录随 RELEASE_EVIDENCE 提供；CI 的 GIMPS 专项会重新运行官方小任务，原有重量级流程在远端继续。
